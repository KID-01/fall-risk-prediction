# 微信小程序对接工作总结

更新时间：2026-08-30

## 一、交付目标

完成 Python 风险后端与微信小程序之间的告警传递链路：后端识别到关注级或高危风险后，通过 CloudBase HTTP 云函数写入告警记录；小程序通过 HTTPS 轮询读取记录，用户可在小程序内确认高危告警。

整体链路如下：

```text
视频/萤石流 → Python 风险分析 → 本地通知记录
                         ↓ HTTPS POST
                 CloudBase fallAlarmPush
                         ↓ action=pull
                    微信小程序告警列表
                         ↓ action=confirm
                       更新已确认状态
```

## 二、后端完成内容

- 增加微信 CloudBase HTTP 通知适配器，后端只负责出站 HTTPS 请求，不要求小程序访问本地 `127.0.0.1:8000`。
- 支持 `action=push`、`action=pull`、`action=confirm` 三类请求契约。
- 使用 `hybrid` 请求格式，同时发送顶层字段和 `data` 详细字段，兼容不同版本的云函数实现。
- 风险通知在本地先落库；云函数失败时不会丢失本地告警，并记录 `cloud_push.status` 和错误信息。
- 通过环境变量配置启用开关、网关地址和请求格式，不把密钥写入小程序或 Git。

## 三、风险级别与推送规则

| 等级 | 值 | 小程序行为 |
| --- | --- | --- |
| 低风险 | `low` | 仅本地记录，不主动推送 |
| 关注级 | `attention` | 写入云端，显示普通提醒 |
| 高危级 | `critical` | 写入云端，显示强提醒并要求确认 |

`riskScore` 为 `0-100` 的工程风险指数，不等同于医学概率或模型准确率。

## 四、推送字段契约

请求：

```json
{
  "action": "push",
  "elderId": "default",
  "riskLevel": "critical",
  "riskScore": 77.5,
  "data": {
    "risk_label": "跌倒高危",
    "title": "跌倒高危告警",
    "message": "人体异常与环境风险叠加，请立即确认现场情况",
    "risk_level": "critical",
    "risk_score": 77.5,
    "isRead": false
  }
}
```

云函数建议保存 `elderId`、`riskLevel`、`riskScore`、`risk_label`、`title`、`message`、`isRead` 和 `createTime`。
