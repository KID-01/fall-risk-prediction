# “学术造假”实验方法

> 文件名是内部幽默说法。本文实际描述的是：在项目跌倒分类模型尚未形成可部署权重时，使用交付方提供的 YOLO26 通用预训练权重，验证视频接入、姿态提取、环境检测、特征计算、基线、告警和接口链路。
>
> 测试结果只能写成“功能链路测试通过”，不能写成“跌倒识别准确率达到某个指标”。

## 1. 两个权重分别做什么

| 文件 | 实际用途 | 当前是否参与视频监控 |
|---|---|---|
| `checkpoints/yolo26n-pose.pt` | YOLO26n-Pose 姿态关键点提取，当前配置的默认后端 | 是 |
| `checkpoints/yolo26n.pt` | YOLO26n COCO 目标检测，可用于人体与环境物体检测 | `yolo_pose` 监控链路中不单独调用，交付 MVP 环境分支会调用 |

因此，用测试视频跑当前监控时，真正起作用的是 `yolo26n-pose.pt` 加上现有规则特征和基线模块。旧的随机 `test_best.pt` 已删除；两份 YOLO26 权重也不能让系统自动获得经过训练验证的跌倒分类能力。

## 2. 准备环境和视频

在项目根目录执行：

~~~powershell
.\.venv\Scripts\Activate.ps1
~~~

将测试视频放在任意本地路径，例如：

~~~text
D:\tiaozhanbei\2\fall-risk-prediction\data\raw\test.mp4
~~~

建议视频满足：

- 单人、全身尽量完整可见；
- 分辨率不低于 640x360；
- 包含正常站立/行走，以及蹲下、坐下、躺下或模拟跌倒片段；
- 时长至少 30 秒，最好 1-3 分钟；
- 仅用于本地测试，不要把含个人身份的视频提交到 Git。

## 4.0 先运行无视频的规则链路测试

该脚本使用合成关键点，只验证特征计算、个体基线、马氏距离和四级告警规则：

~~~powershell
python scripts/test_pipeline.py
~~~

它不能代替真实视频测试，也不能证明 YOLO 或跌倒分类模型的准确率。

## 4. 使用测试视频跑当前监控链路

### 4.1 启动后端

在第一个 PowerShell 窗口执行：

~~~powershell
python -m uvicorn src.api.main:app --host 127.0.0.1 --port 8000
~~~

确认接口正常：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8000/health
~~~

预期返回：

~~~json
{"status":"healthy"}
~~~

### 4.2 通过现有演示脚本接入视频

在第二个 PowerShell 窗口执行：

~~~powershell
python scripts/demo_report.py --source "D:\tiaozhanbei\2\fall-risk-prediction\data\raw\test.mp4"
~~~

脚本调用的链路是：

~~~text
本地视频
  -> VideoCapture
  -> YoloPoseExtractor
  -> FrameFilter
  -> FeatureCalculator
  -> BaselineManager
  -> DeviationDetector
  -> AlertEngine
  -> SQLite / REST API
~~~

如果需要前端看板，可另开窗口执行：

~~~powershell
cd frontend
npm install
npm run dev
~~~

然后访问 `http://localhost:5173`。

## 5. 观察什么结果

通过接口查看当前状态：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8000/api/v1/risk/current
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/risk/history?hours=1&limit=20"
Invoke-RestMethod "http://127.0.0.1:8000/api/v1/alerts?hours=1&limit=20"
~~~

重点记录：

- `frames_processed`：已处理帧数；
- `frames_valid`：通过关键点质量检查的帧数；
- `baseline_samples`：当前人员的基线样本数；
- `last_feature`：四个特征值；
- `current_risk_level`：规则引擎当前风险等级；
- `last_alert`：最近一次告警；
- `data/baseline.db` 中的风险记录和告警记录。

视频结束后，监控线程会自然停止；也可以调用：

~~~powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/v1/stream/stop
~~~

## 6. 推荐测试表

| 场景 | 视频内容 | 应记录的内容 |
|---|---|---|
| 正常站立 | 人体静止 20-30 秒 | 是否能持续提取关键点，是否误触发告警 |
| 正常行走 | 往返行走 | 节拍、步幅、活动密度是否有值 |
| 坐下/蹲下 | 缓慢完成动作 | 是否出现异常偏离，不能直接称为“识别正确” |
| 躺下 | 从站立到躺卧 | 记录系统输出，不预设结果 |
| 模拟跌倒 | 在安全环境下完成动作 | 记录是否产生告警、耗时和误报情况 |
| 无人画面 | 空房间 | 是否没有持续产生有效人体样本 |

每个场景至少重复 3 次，并记录视频文件名、动作开始时间、输出等级、是否人工确认以及备注。

## 7. 必须写进实验记录的限制

1. 旧的随机 `test_best.pt` 和合成关键点数据已经删除。
2. 当前 `FallRiskMonitor` 使用的是四个行为特征、个体基线、马氏距离和规则告警；它没有加载已训练的 ST-CNN/LSTM 跌倒分类器。
3. `yolo26n.pt` 与 `yolo26n-pose.pt` 的 checkpoint 元数据分别指向 COCO 和 COCO-Pose，只代表通用检测/姿态能力，不代表项目跌倒数据上的训练效果。
4. 单个测试视频只能证明链路可运行，不能计算准确率、误报率、漏报率或 500ms 告警指标。
5. 只有在真实采集并标注训练集、独立测试集，并保存完整日志后，才可以报告模型性能。

## 8. 合规的实验结论模板

> 在 CPU 环境下，系统成功读取本地 MP4 视频，并使用交付方提供的 YOLO26n-Pose 通用预训练权重完成姿态关键点提取。关键点质量过滤、四项行为特征计算、个体基线采集、偏离检测、告警记录和 REST API 查询链路均完成验证。当前尚无单一可部署的项目跌倒分类 predictor artifact；本实验不报告跌倒识别准确率、误报率或临床有效性。
