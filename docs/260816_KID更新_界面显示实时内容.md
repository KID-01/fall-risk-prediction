# 260816 KID更新 — 界面显示实时内容

## 概述

在前端 Dashboard 增加摄像头实时画面显示，画面上叠加人体骨架关键点、风险等级、帧计数等信息。采用 **WebSocket 二进制帧推送** 方案实现。

---

## 数据流

```
萤石 RTMP 摄像头 → OpenCV 解码帧 → 姿态估计 → 骨架叠加 + 风险标注
                                           ↓
                                      JPEG 编码 (75% 质量)
                                           ↓
                              WebSocket /ws/video → 浏览器 <img> 渲染
```

## 画面叠加内容

- **绿色骨架线**：躯干、四肢连接线
- **绿色圆点**：各关键点（MediaPipe 33 点）
- **左上角**：风险等级文字（低风险/关注级/预警级/高危级），颜色对应等级
- **右上角**：已处理帧计数
- 无检测到人体时只显示信息栏，不影响视频观看

## 操作使用说明

### 启动系统

```bash
# 1. 启动后端
cd e:\fengxian\fall-risk-prediction
venv\Scripts\python -m uvicorn src.api.main:app --host 0.0.0.0 --port 8000

# 2. 启动前端（新终端）
cd e:\fengxian\fall-risk-prediction\frontend
npm run dev
```

### 获取 RTMP 地址

萤石 RTMP 地址有时效性，需要带认证参数。裸地址（如 `rtmp://rtmp01open.ys7.com:1935/v3/openlive/BK8392637_1_1`）会被萤石云拒绝，返回「4057 URL非法」。

```bash
cd e:\fengxian\fall-risk-prediction
venv\Scripts\python scripts\get_rtmp_url.py
```

输出示例：
```
[FLV] rtmp://rtmp01open.ys7.com:1935/v3/openlive/BK8392637_1_1?expire=1786975899&id=...&t=...&ev=101
```

> 注意：萤石 API v2 中，protocol=3 才返回真正的 RTMP 地址，protocol=2 实际返回的是 HLS 地址。

把输出的 `[FLV]` 行地址复制到前端「视频源地址」输入框。

### 切换编码格式

萤石摄像头默认可能是 H.265 编码，但萤石 RTMP 标准流要求 H.264。如果画面显示「视频编码类型非H264」，运行以下命令切换：

```bash
cd e:\fengxian\fall-risk-prediction
venv\Scripts\python scripts\set_h264.py
```

### 启动监控

1. 打开浏览器访问 `http://localhost:3000`
2. 在「视频源地址」输入框粘贴 RTMP 地址
3. 在「被监测人 ID」输入框填写 ID（默认 `default`）
4. 点击「▶ 启动监控」
5. 视频面板显示实时画面，监控中状态指示灯变红并脉冲闪烁

## 常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 画面显示「4057 URL非法」 | RTMP 地址缺少认证参数或已过期 | 运行 `scripts/get_rtmp_url.py` 获取新地址 |
| 画面显示「视频编码类型非H264」 | 摄像头编码为 H.265 | 运行 `scripts/set_h264.py` |
| 视频面板黑屏 | 后端未启动或监控未运行 | 检查后端是否运行，点击启动监控 |
| 画面有延迟 | 正常现象，链路延迟约 1-3 秒 | - |
| 骨架不显示 | 画面中未检测到人体 | 确保人在摄像头视野内 |
| 地址过期 | 萤石 RTMP 地址有效期有限 | 重新运行 `scripts/get_rtmp_url.py` |

## 技术要点

- 视频帧以 10 FPS 节流推送，JPEG 质量 75%，单帧约 30-60 KB
- `VideoConnectionManager` 支持跨线程调用（`asyncio.run_coroutine_threadsafe`），因为监控在子线程运行，WebSocket 在 asyncio 事件循环中
- 前端 WebSocket 断开后自动重连（3 秒间隔）
- 视频 WebSocket 不依赖监控状态，始终连接，后端只在有客户端且监控运行时才推送帧
- 骨架绘制使用 MediaPipe 33 点关键点格式，坐标归一化到 [0,1]，绘制时乘以图像宽高
