## 二、项目原理与技术架构

### 2.1 系统全链路总览

系统从摄像头视频流到家属端告警，经过 **8 个阶段**的完整处理链路：

```
萤石摄像头 ──RTSP──▶ 视频帧 ──▶ 人体检测 ──▶ 姿态估计 ──▶ 帧质量过滤
                                                      │
                                                      ▼
家属端 ◀──WebSocket── 分级预警 ◀── 偏离检测 ◀── 基线对比 ◀── 四大特征计算
                                                      │
                                                      ▼
                                                   持久化入库
```

### 2.2 萤石视频流接入原理

**目标**：从萤石云摄像头获取实时视频流，供后续姿态分析。

**接入流程**（`src/ezviz/client.py` EzvizClient 类）：

```
① 配置密钥
   configs/ezviz.yaml → appKey + appSecret（已 gitignore 保护）

② 获取 AccessToken
   POST https://open.ys7.com/api/lapp/token/get
   携带 appKey/appSecret → 返回 accessToken（有效期 7 天）
   自动缓存 + 提前 5 分钟刷新 + 失败指数退避重试（最多 3 次）

③ 查询设备列表
   POST /api/lapp/device/list → 返回设备序列号 deviceSerial、在线状态

④ 获取视频流地址
   POST /api/lapp/live/address/get
   携带 accessToken + deviceSerial + protocol
   支持 4 种协议：HLS(Web播放) / RTMP / FLV / RTSP(OpenCV拉流)

⑤ OpenCV 拉流
   EzvizClient.get_rtsp_url() → RTSP 地址
   → 传入 VideoCapture(source=rtsp_url)
   → cv2.VideoCapture 逐帧读取 → VideoFrame 数据结构
   → 帧采样降频 15fps→10fps（降低计算负载）
```

**当前状态**：①②③ 步骤已验证通过（Token 获取成功），④⑤ 代码就绪，**待设备激活后即可拉到真实视频流**。

### 2.3 姿态估计：从视频帧到骨骼关键点

**目标**：从每一帧视频中提取人体骨骼关键点，作为后续特征计算的输入。

**双后端设计**（`configs/base.yaml` 的 `pose_estimation.backend` 字段一键切换）：

| 后端 | 模型 | 关键点数 | 推理方式 |
|------|------|---------|---------|
| `mediapipe`（默认） | MediaPipe PoseLandmarker Lite | 33 点 (x,y,z,visibility) | 独立人体检测 + 姿态估计两次推理 |
| `yolo_pose` | YOLOv8n-Pose | 17 点 COCO → 映射为 33 点 | 一次推理同时完成检测+姿态 |

**统一输出格式**：无论哪个后端，均输出 `KeypointFrame(33, 4)`，下游代码无感知。

**工厂函数**（`src/data/keypoint_extractor.py`）：
```python
def create_keypoint_extractor():
    backend = config.pose_estimation.backend  # "mediapipe" 或 "yolo_pose"
    if backend == "yolo_pose":
        return YoloPoseExtractor()   # YOLOv8n-Pose 一次推理
    else:
        return KeypointExtractor()   # MediaPipe 两次推理
```

**帧质量过滤**（`src/data/frame_filter.py`）：
- 置信度阈值过滤（visibility > 0.5）
- 下肢 6 个关键点至少 4 个可见
- 躯干 4 个关键点至少 3 个可见
- 不通过的帧标记 `is_valid=False`，跳过后续处理

### 2.4 四大步态特征计算

**目标**：将骨骼关键点时序序列转化为 4 个量化指标，描述老人的步态模式。

**输入**：最近 30 帧关键点序列 `[(33,4)] × 30`

**输出**：`FeatureVector(walking_rhythm, step_amplitude, trunk_stability, activity_density)`

| 特征 | 计算方法 | 含义 |
|------|---------|------|
| **行走节拍频率** | 髋关节 y 坐标做 FFT，取 0.5-5Hz 范围内主频 | 步频，反映行走节奏（正常约 1.5-2.5Hz） |
| **步幅相对幅度** | 踝关节摆动幅度 ÷ 躯干高度归一化 | 步子大小，反映步伐稳定性 |
| **躯干稳定指数** | 肩髋连线与垂直方向夹角的变化范围 | 身体是否前倾/摇晃，反映平衡能力 |
| **活动密度** | 髋部位移超阈值的帧占比 (0~1) | 运动量，反映活跃程度 |

> **设计要点**：四大特征均为**相对值**（归一化/比值），不依赖物理尺度标定，适配不同摄像头安装距离和角度。

### 2.5 个体化基线与偏离检测

**目标**：建立每位老人专属的"正常步态基线"，检测当前步态是否偏离正常范围——这是"前置预防"的核心。

**基线采集**（`src/inference/baseline.py`）：
- 系统部署后前 **7 天**为基线采集期
- 累计至少 **100 个**有效特征样本
- 计算四维特征的：均值 `mean`、标准差 `std`、协方差逆矩阵 `cov_inv`
- 持久化到 SQLite，支持多用户

**双层偏离检测**（`src/inference/deviation.py`）：

| 层级 | 时间尺度 | 方法 | 触发条件 |
|------|---------|------|---------|
| **第一层（短期）** | 5 分钟窗口 / 30 秒步长 | 马氏距离 | 连续 3 个窗口马氏距离 > 3.0（p<0.01） |
| **第二层（长期）** | 14 天窗口 | 线性回归斜率 | 连续 7 天负向变化超过阈值 |

**马氏距离**：考虑特征间相关性的多维偏离度量，比简单的 Z-Score 更准确。
```
D² = (x - mean)ᵀ · cov_inv · (x - mean)
```

> **关键价值**：老人 A 的"正常"与老人 B 不同。系统为每人建模，避免一刀切阈值，实现个体化精准预警。

### 2.6 核心大模型：多模态跌倒风险预测

**目标**：融合时序关键点 + 步态特征 + 环境风险，端到端预测跌倒风险评分和等级。

**模型架构**（`src/models/fall_risk_predictor.py` FallRiskPredictor）：

```
输入三路数据：
  ① 骨骼关键点时序  (B, T=90, 33, 3)  ← 6 秒关键点序列
  ② 步态手工特征    (B, 4)             ← 四大特征向量
  ③ 环境风险特征    (B, 5)             ← 环境感知模块（T4.x 待完成）

         │
         ▼
  ┌──────────────────────────────────┐
  │  TemporalEncoder（时序编码器）      │
  │  Transformer Encoder 4层 8头      │
  │  (B,T,33,3)→展平→投影256维         │
  │  +CLS token + 位置编码             │
  │  → 输出全局特征 (B, 256)           │
  └──────────────────────────────────┘
         │ global_feat (B,256)
         ▼
  ┌──────────────────────────────────┐
  │  MultiModalFusion（多模态融合）     │
  │  Cross-Attention 三路融合：        │
  │  Query = global_feat (256维)      │
  │  Key/Value = gait(4→128) +        │
  │              env(5→64) = 192维     │
  │  → 残差 + FFN + LayerNorm          │
  │  → 输出融合特征 (B, 256)           │
  └──────────────────────────────────┘
         │ fused_feat (B,256)
         ▼
  ┌──────────────────────────────────┐
  │  RiskPredictionHead（风险预测头）   │
  │  回归头：MLP(256→128→64→1)         │
  │         +Sigmoid → [0,100]        │  → risk_score
  │  分类头：MLP(256→128→4)            │  → risk_probs (4级)
  └──────────────────────────────────┘
```

**多任务损失**（`MultiTaskLoss`）：
```
Loss = α·MSE(风险评分) + β·CrossEntropy(风险等级) + γ·OrdinalLoss(序数约束)
```
- MSE：回归损失，预测连续风险分
- CrossEntropy：分类损失，预测 4 级风险
- OrdinalLoss：序数损失，约束"高危>预警>关注>低风险"的有序关系

**训练管线**（`scripts/train.py`）：
- AdamW 优化器 + CosineAnnealingWarmRestarts 学习率调度
- 混合精度训练（AMP）加速
- 早停（patience=10）+ Checkpoint 保存 best.pt

### 2.7 分级预警与实时推送

**四级预警引擎**（`src/alerts/engine.py`）：

| 等级 | 触发条件 | 响应动作 |
|------|---------|---------|
| 🟢 低风险 | 所有特征在基线±1σ内 | 持续监测，不推送 |
| 🟡 关注级 | 短期偏离≥3次/小时 | APP 推送提醒家属 |
| 🟠 预警级 | 长期趋势连续 7 天下降 | 短信通知，建议体检 |
| 🔴 高危级 | 近似跌倒 / 4 小时无活动 | 电话通知，立即确认 |

**实时推送**：告警事件通过 WebSocket（`/ws/alerts`）实时推送到家属端看板，同时落盘 SQLite。

### 2.8 从视频到预警的完整数据流

```
萤石摄像头 (RTSP)
    │
    ▼ VideoCapture 逐帧读取 (10fps)
视频帧 (1280×720 RGB)
    │
    ├─▶ [阶段1] YOLOv8n 人体检测 → 检测框
    │        (yolo_pose 后端跳过此步，姿态模型自带检测)
    │
    ▼
    ├─▶ [阶段2] 姿态估计 → KeypointFrame(33,4) 骨骼关键点
    │        MediaPipe 或 YOLOv8n-Pose
    │
    ▼
    ├─▶ [阶段3] 帧质量过滤 → 下肢可见性+躯干完整性检查
    │        丢弃不合格帧
    │
    ▼
    ├─▶ [阶段4] 四大特征计算 → FeatureVector(4维)
    │        累积 30 帧窗口 → FFT/幅度/角度/密度
    │
    ▼
    ├─▶ [阶段5] 基线采集/对比
    │        前7天建基线 → 后续计算马氏距离
    │
    ▼
    ├─▶ [阶段6] 双层偏离检测
    │        短期(5分钟马氏距离) + 长期(14天趋势)
    │
    ▼
    ├─▶ [阶段7] 四级预警评估 → RiskLevel + AlertEvent
    │        低/关注/预警/高危
    │
    ▼
    └─▶ [阶段8] 持久化 + WebSocket 推送
             SQLite 落盘 + 家属端实时刷新
```

> **隐私保护**：原始视频帧在边缘端处理后立即丢弃，仅骨骼关键点（2-5KB/包）参与计算和传输，无法逆向还原影像。

### 2.9 双路径风险判断架构

系统设计了**两条并行的风险判断路径**，当前汇报演示使用路径A（规则引擎），路径B（深度模型）为升级方向：

#### 路径A：规则引擎（当前可用，已上线）

```
YOLOv8n-Pose → 33关键点 → 四大特征 → 个体化基线（马氏距离）→ 双层偏离检测 → 四级预警
```

| 环节 | 方法 | 优势 |
|------|------|------|
| 姿态估计 | YOLOv8n-Pose 预训练模型 | 无需训练，开箱即用 |
| 特征计算 | FFT + 归一化 + 统计量 | 确定性算法，可解释 |
| 偏离检测 | 马氏距离（考虑特征相关性） | 个体化基线，非一刀切阈值 |
| 预警判断 | 规则引擎（短期+长期双层） | 规则透明，可调参 |

> 当前接入 `yolo26n-pose.pt` 通用预训练姿态权重。它可用于工程链路演示，但不是项目跌倒分类训练成果。

#### 路径B：深度模型（训练中，升级方向）

```
关键点时序(90帧) + 步态特征(4维) + 环境风险(5维)
    → FallRiskPredictor (Transformer + CrossAttention)
    → 风险评分[0-100] + 4级分类概率
```

| 对比维度 | 路径A（规则引擎） | 路径B（深度模型） |
|---------|------------------|------------------|
| 依赖 | YOLO-Pose 预训练模型 ✅ | 自训练 best.pt 权重 ❌ |
| 输出 | 马氏距离 + 风险等级 | 风险评分[0-100] + 概率分布 |
| 能力 | 偏离检测（是否异常） | 精细评分 + 多因素融合 |
| 可解释性 | 高（规则透明） | 中（注意力权重可分析） |
| 当前状态 | **可用** | 代码就绪，训练集采集+算法迭代中 |

> **汇报策略**：演示路径A跑通完整链路（视频→关键点→特征→基线→预警），路径B作为"正在迭代的深度学习升级"介绍架构设计。待训练数据集就绪后，路径B产出权重即可无缝接入，替换规则引擎输出。
