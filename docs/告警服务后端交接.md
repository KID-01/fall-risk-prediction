# 告警服务后端交接文档

版本：risk-notification-v1  
更新时间：2026-08-29

## 1. 当前完成状态

后端告警编排、本地持久化、WebSocket 主动通知、REST 查询、告警确认和红色告警 30 秒电话兜底状态机已经完成，并已通过现有后端测试。

当前尚未完成公网端到端验收，原因如下：

- 微信云函数 HTTP 上报适配器已经实现，但默认关闭，尚未在当前环境使用真实公网地址完成联调确认。
- APP、短信、电话供应商尚未接入，相关投递记录会标记为 `not_configured`。
- 后端接口当前没有认证中间件，生产环境需要由网关或小程序后端增加 HTTPS、鉴权和限流。

因此，本版本适合进入小程序联调，不应标记为第三方通知服务最终上线版本。

## 2. 小程序开发团队必须完成的工作

以下事项是本次交接的主要开发任务，建议按顺序完成：

### 2.1 小程序启动初始化

- 从后端 `GET /api/v1/notifications/policy` 读取风险策略，不要在小程序代码中硬编码分数阈值。
- 保存后端基础地址配置；生产环境使用 HTTPS，WebSocket 使用 `wss://`。
- 页面加载后建立 `/ws/alerts` 连接，并显示连接状态。

### 2.2 WebSocket 实时通知

- 每 20–30 秒发送 `{"type":"ping"}`，收到 `{"type":"pong"}` 视为连接正常。
- 收到 `type=risk_notification` 时，使用 `data.notification_id` 去重。
- `risk_level=attention`：显示普通页面提醒，不显示确认按钮。
- `risk_level=critical`：显示强提醒、风险分、原因和“我已确认”按钮。
- 同一个 `notification_id` 后续收到 `fallback.state=triggered` 时只更新原提醒状态，不重复弹窗。
- WebSocket 断开后自动重连，建议采用递增重试间隔；重连成功后立即执行通知补偿查询。
- 保留并兼容 `risk_update`，但不能把它当作主动告警消息。

### 2.3 通知历史和断线补偿

- 页面进入或 WebSocket 重连后调用：
  `GET /api/v1/notifications?acknowledged=0&limit=50`
- 实现通知历史列表，至少展示时间、风险等级、风险分、消息和处理状态。
- 收到实时消息和历史消息均按 `notification_id` 去重，避免断线补偿造成重复提醒。
- 通知详情需要展示 `deliveries`、`fallback.state` 和 `cloud_push.status`（如有）。

### 2.4 高危告警确认

- 红色告警必须展示确认按钮，并调用：
  `POST /api/v1/alerts/{alert_id}/acknowledge`
- 确认成功后刷新通知详情，显示 `acknowledged=true` 和 `fallback.state=cancelled`。
- 确认请求需要幂等处理：按钮提交期间禁用，重复点击不得创建新告警。
- 如果已经收到 `fallback.state=triggered`，仍允许确认，但页面应保留“电话兜底已触发”的历史状态。

### 2.5 页面交互建议

- 黄色：顶部或列表内普通提醒，可点击查看详情。
- 红色：明显的强提醒弹窗/页面，显示“立即确认”操作，并突出 30 秒倒计时状态。
- 历史列表：支持按风险等级和是否已确认筛选。
- `cloud_push.status=failed` 时显示“云端通知投递失败”，但不要修改后端风险等级。
- `risk_score` 仅显示为 0–100 工程风险指数，不得标注为医学概率。

### 2.6 联调配置与验收

- 向后端开发人员确认测试环境基础 URL、`person_id`（对应 `elderId`）和 WebSocket 地址。
- 使用测试视频触发 attention 和 critical，分别验证普通提醒、强提醒和确认流程。
- 验证断网、重连、重复消息、接口超时和错误响应。
- 验证 critical 超过 30 秒未确认后，原通知 ID 的 `fallback.state` 更新为 `triggered`。
- 云函数订阅消息由云函数团队负责；小程序侧只需展示后端状态并完成确认接口调用。
- 真机验收必须使用 `wss://`，并验证微信订阅消息授权和模板配置。

## 3. 后端已实现能力

- 风险等级：`low`、`attention`、`critical`。内部 `warning` 对外映射为 `attention`。
- `low`：仅本地风险/告警记录，不广播主动告警。
- `attention`：通过 `/ws/alerts` 发送 `risk_notification`，供小程序页面提醒。
- `critical`：发送 WebSocket 通知，同时记录 APP/SMS 投递桩；30 秒未确认后生成电话 `triggered` 记录。
- 任一授权客户端确认告警后，红色电话兜底从 `scheduled` 变为 `cancelled`。
- 服务重启时会恢复未确认的红色兜底任务。
- 通知使用不透明 `notification_id`，不返回服务器文件路径。

## 4. 小程序接入接口

### 策略

```http
GET /api/v1/notifications/policy
```

小程序启动时读取策略，不要在客户端根据风险分数自行推导等级。

### 通知列表

```http
GET /api/v1/notifications?person_id=E001&risk_level=critical&acknowledged=0&limit=50
```

返回通知事件、`deliveries` 投递状态、确认状态和电话兜底状态。WebSocket 断线重连后使用该接口做补偿查询。

### 通知详情

```http
GET /api/v1/notifications/{notification_id}
```

### 告警确认

```http
POST /api/v1/alerts/{alert_id}/acknowledge
```

该接口幂等。高危通知确认后，关联通知的 `acknowledged=true`，且 `fallback.state=cancelled`。

旧接口保持兼容：

```http
GET /api/v1/alerts
```

## 5. WebSocket 接入

连接地址：

```text
ws://<后端地址>/ws/alerts
```

生产和真机环境必须使用 `wss://`。

客户端每 20–30 秒发送：

```json
{"type":"ping"}
```

服务端返回：

```json
{"type":"pong"}
```

主动告警消息类型为 `risk_notification`：

```json
{
  "type": "risk_notification",
  "data": {
    "notification_id": "uuid",
    "alert_id": 123,
    "risk_level": "critical",
    "risk_label": "高危级",
    "risk_score": 86.4,
    "person_id": "E001",
    "device_id": "camera-01",
    "occurred_at": 1712345678.0,
    "title": "跌倒风险告警",
    "message": "人体异常与环境风险叠加，请立即确认现场情况",
    "reason_codes": ["human_high", "interaction_high"],
    "channels": ["websocket", "app", "sms"],
    "ack_required": true,
    "ack_deadline_at": 1712345708.0,
    "fallback": {
      "enabled": true,
      "channel": "phone",
      "state": "scheduled"
    },
    "cloud_push": {
      "enabled": false,
      "status": "not_configured"
    }
  }
}
```

`risk_update` 仍用于看板状态同步，不应当被当作主动告警。小程序应按 `notification_id` 去重；红色通知在电话兜底状态变化时可能再次广播同一 ID。

## 7. 联调验收顺序

1. 小程序读取 `/api/v1/notifications/policy`，确认只存在 `low/attention/critical`。
2. 连接 `/ws/alerts`，验证 `ping/pong` 和 `risk_notification` 字段。
3. 触发黄色告警，确认只显示页面提醒且无需确认。
4. 触发红色告警，确认出现确认按钮，调用确认接口后 `fallback.state=cancelled`。
5. 不确认红色告警，等待 30 秒，确认状态变为 `triggered`，并按原 `notification_id` 更新页面，不重复弹窗。
6. 设置云函数环境变量，使用 `E001` 触发一次告警，确认云函数返回 `code=0` 且通知详情 `cloud_push.status=sent`。
7. 模拟云函数超时或非 0 返回，确认本地告警和 WebSocket 仍正常，状态为 `failed`。
8. 断开 WebSocket 后重连，调用通知列表接口补偿未读通知。

## 8. 生产注意事项

- 风险等级和风险分必须以 Python 后端为准，小程序不得自行计算或篡改。
- 风险分是工程风险指数，不是医学概率或临床诊断。
- 公网部署必须使用 HTTPS/WSS，并增加鉴权、限流、审计和来源校验。
- 不要把云函数 URL、内部路径或供应商密钥写入小程序前端代码。
- APP、短信、电话真实供应商接入时，应替换后端适配器，不修改通知事件字段和确认状态机。
