# 官方测试集使用方法

## 1. 数据集说明

本文针对 University of Rzeszow 发布的 UR Fall Detection Dataset：

- 官方页面：https://fenix.ur.edu.pl/mkepski/ds/uf.html
- 数据规模：70 个序列，其中 30 个跌倒序列、40 个日常活动（ADL）序列；
- 数据类型：RGB、深度图、同步信息和加速度数据；
- 跌倒序列：两个 Kinect 视角；
- ADL 序列：仅 camera 0；
- 加速度设备：PS Move（60 Hz）和 x-IMU（256 Hz）。

本数据集适合用于：

- 跌倒/非跌倒分类原型；
- 时序模型预训练；
- YOLO-Pose 关键点提取链路验证；
- RGB 与加速度多模态实验；
- 不同模型结构的基准对比。

它不能单独作为项目最终效果证明。最终指标仍需使用萤石摄像头采集的真实场景数据验证。

## 2. 许可与引用要求

官方页面声明数据集采用 CC BY-NC-SA 4.0：

- 允许非商业学术研究；
- 使用时需要署名；
- 衍生内容需要按相同许可方式共享；
- 商业用途需联系数据集作者取得许可。

建议在数据目录保存来源、访问日期和许可证说明，但不要修改官方原始文件。

汇报和论文中应引用：

> Bogdan Kwolek, Michal Kepski, Human fall detection on embedded platform using depth maps and wireless accelerometer, Computer Methods and Programs in Biomedicine, Volume 117, Issue 3, 2014, Pages 489-501.

## 3. 推荐目录结构

不要把公开数据混入现有的合成测试样本目录。推荐结构：

~~~text
data/
  external/
    urfall/
      raw/
        videos/
        sync/
        accelerometer/
      metadata/
        urfall-cam0-falls.csv
        urfall-cam0-adls.csv
        sha256.csv
  processed/
    urfall/
  keypoints/
    urfall/
  labels/
    urfall_labels.json
    urfall_split.json
~~~

`data/external/`、`data/processed/` 和真实训练数据应由 DVC 或独立数据盘管理，不建议直接上传到普通 Git/Git LFS。

## 4. 下载数据

### 4.1 激活项目环境

~~~powershell
& ./.venv/Scripts/Activate.ps1
~~~

### 4.2 创建目录

~~~powershell
New-Item -ItemType Directory -Force data/external/urfall/raw/videos
New-Item -ItemType Directory -Force data/external/urfall/raw/sync
New-Item -ItemType Directory -Force data/external/urfall/raw/accelerometer
New-Item -ItemType Directory -Force data/external/urfall/metadata
~~~

### 4.3 下载 camera 0 视频和同步数据

优先使用 camera 0，因为跌倒和 ADL 都有该视角，数据格式较一致。

~~~powershell
$base = "https://fenix.ur.edu.pl/mkepski/ds/data"

1..30 | ForEach-Object {
    $id = $_.ToString("00")
    Invoke-WebRequest "$base/fall-$id-cam0.mp4" `
        -OutFile "data/external/urfall/raw/videos/fall-$id-cam0.mp4"
    Invoke-WebRequest "$base/fall-$id-data.csv" `
        -OutFile "data/external/urfall/raw/sync/fall-$id-data.csv"
    Invoke-WebRequest "$base/fall-$id-acc.csv" `
        -OutFile "data/external/urfall/raw/accelerometer/fall-$id-acc.csv"
}

1..40 | ForEach-Object {
    $id = $_.ToString("00")
    Invoke-WebRequest "$base/adl-$id-cam0.mp4" `
        -OutFile "data/external/urfall/raw/videos/adl-$id-cam0.mp4"
    Invoke-WebRequest "$base/adl-$id-data.csv" `
        -OutFile "data/external/urfall/raw/sync/adl-$id-data.csv"
    Invoke-WebRequest "$base/adl-$id-acc.csv" `
        -OutFile "data/external/urfall/raw/accelerometer/adl-$id-acc.csv"
}
~~~

### 4.4 下载官方汇总标签/特征文件

~~~powershell
Invoke-WebRequest "$base/urfall-cam0-falls.csv" `
    -OutFile "data/external/urfall/metadata/urfall-cam0-falls.csv"

Invoke-WebRequest "$base/urfall-cam0-adls.csv" `
    -OutFile "data/external/urfall/metadata/urfall-cam0-adls.csv"
~~~

### 4.5 生成文件哈希

~~~powershell
Get-ChildItem data/external/urfall -Recurse -File |
    Get-FileHash -Algorithm SHA256 |
    Select-Object Path, Hash |
    Export-Csv data/external/urfall/metadata/sha256.csv -NoTypeInformation
~~~

哈希用于确认文件没有被意外替换，也便于复现实验。

## 5. 官方标签含义

官方汇总 CSV 中的帧级标签含义：

| 标签 | 官方含义 | 本项目建议 |
|---:|---|---|
| `-1` | 人体没有躺倒 | normal/not-lying |
| `0` | 跌倒过程中的过渡姿态 | fall-transition |
| `1` | 人体躺在地面 | lying |

不能直接把 `1` 当作“检测到跌倒”，因为主动躺下也可能产生躺卧姿态。模型必须结合连续动作轨迹，而不是只看最后一帧。

建议先采用以下两种任务之一：

### 任务 A：序列级二分类

~~~text
fall sequence -> fall
adl sequence  -> non-fall
~~~

优点是实现简单，适合先验证训练链路；缺点是不能区分蹲下、坐下、躺下等动作，也不能精确定位跌倒时刻。

### 任务 B：窗口级三分类

~~~text
normal/not-lying
fall-transition
lying
~~~

按连续 30-90 帧划分窗口，并用官方帧号对齐标签。这更适合 LSTM/ST-CNN，但需要专门的数据导入脚本保留原始帧号。

## 6. 视频预处理

现有脚本可以把 MP4 转换为人体 ROI 帧：

~~~powershell
python scripts/preprocess_videos.py `
    --input data/external/urfall/raw/videos `
    --output data/processed/urfall `
    --fps 10 `
    --size 256 256
~~~

输出示例：

~~~text
data/processed/urfall/fall-01-cam0/*.jpg
data/processed/urfall/adl-01-cam0/*.jpg
~~~

注意：当前脚本重新编号采样后的帧，无法精确保留官方原始帧号。因此：

- 序列级 fall/ADL 二分类可以先使用；
- 帧级 `-1/0/1` 标签对齐不能直接使用；
- 精确时序训练需要新增 UR Fall 导入脚本，记录“原始帧号 -> 采样帧号”的映射。

## 7. 提取 YOLO-Pose 关键点

项目模型期望的关键点文件格式：

~~~text
(T, 33, 4)
~~~

四列含义：

~~~text
x, y, z, visibility
~~~

当前 `scripts/extract_keypoints.py` 存在一个重要限制：它硬编码使用 `KeypointExtractor`（MediaPipe），没有使用当前配置中的 `YoloPoseExtractor`。

因此，在未修改该脚本之前，不应直接把它当作 YOLO-Pose 批处理命令。需要先完成以下修改之一：

1. 将 `KeypointExtractor()` 改为 `create_keypoint_extractor()`；
2. 新建 `scripts/import_urfall.py`，直接使用 `YoloPoseExtractor` 读取视频并保存关键点；
3. 同时保存每个关键点窗口对应的序列名、原始帧号和标签。

修改完成后，预期命令形式为：

~~~powershell
python scripts/extract_keypoints.py `
    --input data/processed/urfall `
    --output data/keypoints/urfall
~~~

每个输出文件都应验证：

~~~text
dtype=float32
shape=(T, 33, 4)
T > 0
坐标和置信度均为有限数值
~~~

## 8. 标签文件格式

当前 `FallRiskDataset` 按关键点文件名读取标签，建议生成：

~~~json
{
  "fall-01-cam0": {
    "action": "fall",
    "risk_score": 100.0,
    "risk_level": 3,
    "source": "UR Fall Detection Dataset"
  },
  "adl-01-cam0": {
    "action": "adl",
    "risk_score": 0.0,
    "risk_level": 0,
    "source": "UR Fall Detection Dataset"
  }
}
~~~

上述风险分数只适合训练链路原型，不能解释为医学风险评分。更严谨的做法是新增独立的 `action_label`，由行为分类模型预测 fall/ADL，再由业务规则转换为风险等级。

## 9. 数据划分

不能随机拆分单帧，否则同一视频的相邻帧可能同时进入训练集和测试集，形成数据泄漏。

最低要求：

- 以完整序列为单位划分；
- 同一序列的 camera 0/camera 1 必须放在同一集合；
- 固定随机种子；
- 将划分结果保存为 `data/labels/urfall_split.json`；
- 测试集一旦确定，不参与调参或训练。

数据量只有 70 个序列，推荐使用：

- 5 折交叉验证用于模型选择；
- 额外保留一组完全不参与训练和调参的最终测试序列；
- 有可靠人员编号时，优先按人员划分，避免身份特征泄漏。

## 10. 接入当前训练代码前的阻塞项

当前 `scripts/train.py` 中仍然是：

~~~python
labels=None  # TODO: 加载真实标签
~~~

这意味着直接运行训练脚本时，所有样本会使用默认的 `risk_score=0`、`risk_level=0`，得到的模型没有有效意义。

正式训练前必须完成：

1. 增加 `--labels` 参数；
2. 加载 `urfall_labels.json`；
3. 按 `urfall_split.json` 建立固定训练/验证/测试集合；
4. 验证每个关键点文件都能找到标签；
5. 记录模型、数据、配置和代码版本；
6. 将最佳模型保存为独立文件，不覆盖官方 YOLO 权重。

完成这些修改后，训练命令才可以写成：

~~~powershell
python scripts/train.py `
    --data-dir data/keypoints/urfall `
    --epochs 100 `
    --batch-size 16 `
    --device cpu
~~~

注意：以上命令在标签加载功能完成前不能用于有效训练。

## 11. 推荐的实际使用路线

### 第一阶段：验证公开数据链路

- 先下载 2 个 fall 和 2 个 ADL 视频；
- 验证视频能打开；
- 验证 YOLO-Pose 能提取人体关键点；
- 验证关键点文件形状；
- 验证标签能够正确匹配。

### 第二阶段：完整转换

- 下载 camera 0 的 70 个视频；
- 批量提取关键点；
- 生成标签和固定划分；
- 输出转换失败清单；
- 统计有效帧比例。

### 第三阶段：模型预训练

- 先训练 fall/ADL 二分类基线；
- 再实现窗口级 LSTM/ST-CNN；
- 保存每次实验的配置、日志和 checkpoint；
- 使用相同测试集比较不同模型。

### 第四阶段：萤石数据适配

- 使用萤石摄像头采集本项目场景；
- 对蹲下、坐下、主动躺下、跌倒等行为重新标注；
- 用公开数据预训练权重进行微调；
- 最终性能只在萤石独立测试集上报告。

## 12. 可报告与不可报告的结论

可以报告：

- 使用 UR Fall 数据完成了公开数据预训练；
- 视频、关键点、标签和训练链路已经跑通；
- 不同模型在固定公开测试划分上的对比结果；
- 萤石数据用于后续场景微调。

暂时不能报告：

- 系统误报率低于 5%；
- 支持 15 米可靠检测；
- 500 ms 内完成端到端告警；
- 对蹲下、躺卧和跌倒完成准确区分；
- 公开数据结果等同于萤石真实场景结果。
