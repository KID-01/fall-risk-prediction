# 微信小程序推送服务交接文档

版本：`risk-notification-v1`
适用系统：跌倒风险预测系统
当前实现：后端通知编排、WebSocket 推送、REST 查询、投递状态记录和电话兜底状态机。

## 1. 风险等级与渠道策略

系统对外固定提供三档风险等级，没有橙色等级：

| 颜色 | `risk_level` | 含义 | 主动渠道 | 确认要求 |
|---|---|---|---|---|
| 绿色 | `low` | 低风险 | 无，仅本地日志和风险记录 | 否 |
| 黄色 | `attention` | 关注级 | WebSocket 看板提醒 | 否 |
| 红色 | `critical` | 高危级 | WebSocket + APP + 短信 | 是，30 秒内确认 |

内部历史引擎仍可能产生 `warning`（长期趋势告警）。通知服务会将它映射为对外黄色 `attention`，历史告警记录中的原始等级不修改。

APP、短信和电话目前不调用第三方供应商，投递状态为 `not_configured`。微信小程序成员负责实现实际消息展示；短信/电话供应商适配由后续后端成员完成。

## 2. REST 接口

基础地址示例：`http://localhost:8000`

### 2.1 获取策略

```http
GET /api/v1/notifications/policy
```

用于小程序启动时读取等级、渠道和确认规则。响应中的 `levels` 是唯一可信策略，客户端不得自行根据分数推导渠道。

### 2.2 查询通知

```http
GET /api/v1/notifications?person_id=default&acknowledged=0&hours=24&limit=50&offset=0
GET /api/v1/notifications/{notification_id}
```

可选过滤参数：`person_id`、`device_id`、`risk_level`（`low/attention/critical`）、`acknowledged`（`0/1`）、`hours`、`limit`、`offset`。

响应示例：

```json
{
  "total": 1,
  "notifications": [
    {
      "notification_id": "a1b2c3...",
      "alert_id": 123,
      "risk_level": "critical",
      "risk_label": "高危级",
      "source_risk_level": "critical",
      "risk_score": 86.4,
      "person_id": "default",
      "device_id": "camera-01",
      "occurred_at": 1712345678.0,
      "title": "跌倒风险告警",
      "message": "人体异常与环境风险叠加，请立即确认现场情况",
      "reason_codes": ["human_high", "interaction_high"],
      "channels": ["websocket", "app", "sms"],
      "ack_required": true,
      "acknowledged": false,
      "acknowledged_at": null,
      "ack_deadline_at": 1712345708.0,
      "fallback": {
        "enabled": true,
        "channel": "phone",
        "state": "scheduled"
      },
      "deliveries": [
        {"channel": "websocket", "status": "queued"},
        {"channel": "app", "status": "not_configured"},
        {"channel": "sms", "status": "not_configured"}
      ]
    }
  ]
}
```

`fallback.state` 的取值：

- `null`：该等级没有电话兜底。
- `scheduled`：红色通知已创建，等待确认或 30 秒截止。
- `cancelled`：已确认，电话兜底取消。
- `triggered`：30 秒未确认，已生成电话渠道投递记录。

### 2.3 查询和确认告警

```http
GET /api/v1/alerts?person_id=default&acknowledged=0&limit=50
POST /api/v1/alerts/{alert_id}/acknowledge
```

小程序对红色通知调用现有告警确认接口即可。确认是幂等操作；任意已连接客户端确认后，关联通知的 `acknowledged` 变为 `true`，`scheduled` 电话兜底变为 `cancelled`。旧告警没有通知关联时，仍按原接口行为处理。

## 3. WebSocket 实时通道

端点：`ws://<host>/ws/alerts`，生产环境必须使用 `wss://`。

客户端每 20~30 秒发送：

```json
{"type":"ping"}
```

服务端回复：

```json
{"type":"pong"}
```

黄色和红色主动通知使用：

```json
{
  "type": "risk_notification",
  "data": {
    "notification_id": "a1b2c3...",
    "risk_level": "attention",
    "risk_label": "关注级",
    "risk_score": 45.2,
    "person_id": "default",
    "device_id": "camera-01",
    "occurred_at": 1712345678.0,
    "title": "跌倒风险告警",
    "message": "检测到人体或环境风险变化，建议持续关注",
    "reason_codes": ["human_medium"],
    "channels": ["websocket"],
    "ack_required": false,
    "ack_deadline_at": null,
    "fallback": {"enabled": false, "channel": null, "state": null}
  }
}
```

红色通知初次推送后，30 秒未确认会再次推送同一个 `notification_id`，但 `fallback.state` 变为 `triggered`，并包含电话投递状态。小程序必须按 `notification_id` 去重，按状态更新同一条通知。

现有 `risk_update` 消息继续存在，用于 Web 看板刷新当前风险状态；它不是主动通知，不能替代 `risk_notification`。

## 4. 推荐接入流程

1. 小程序启动时请求 `/api/v1/notifications/policy`。
2. 建立 `/ws/alerts`，处理 `pong`、`risk_notification` 和兼容的 `risk_update`。
3. 连接断开后重连；重连成功按最后同步时间调用 `/api/v1/notifications` 补偿未读通知。
4. 收到黄色通知时显示普通看板提醒。
5. 收到红色通知时显示强提醒和“我已确认”按钮，按钮调用 `/api/v1/alerts/{alert_id}/acknowledge`。
6. 收到 `fallback.state=triggered` 时显示“电话兜底已触发/待接入”状态，不重复创建本地通知。

## 5. 适配器边界

通知服务已经把渠道分为 `websocket`、`app`、`sms`、`phone`。后续接入真实供应商时：

- APP 适配器接收完整通知事件，返回供应商消息 ID和发送状态。
- 短信适配器只负责发送红色通知的摘要、人员和设备标识，不发送内部路径或敏感视频数据。
- 电话适配器只在 `fallback.state=triggered` 后执行，执行结果写回对应投递记录。
- 适配器失败应记录 `failed` 和 `error_message`，不能改变风险等级或伪造发送成功。

## 6. 安全与联调约束

- 当前项目沿用内网无鉴权 API；生产部署必须由网关或小程序后端增加 HTTPS、鉴权、限流和来源校验。
- 风险等级、风险分和原因码以服务端事件为准，不信任客户端上报值。
- `notification_id` 是不透明标识；接口不会返回服务器文件路径。
- 风险分是 `0–100` 工程风险指数，不是跌倒概率或医学诊断结果。
- 联调时可使用 `data/raw/test.mp4` 触发风险链路；APP、短信、电话预期为 `not_configured`，不应要求真实外发。

## 7. 验收清单

- 能读取三档策略，且不存在橙色对外等级。
- 黄色只收到 WebSocket 主动通知。
- 红色收到 WebSocket 事件并看到 APP/SMS `not_configured` 投递记录。
- 红色 30 秒内确认后电话状态为 `cancelled`。
- 红色超过 30 秒未确认后电话状态为 `triggered`，且事件 ID不变。
- WebSocket 断线后可通过 REST 找回未确认通知。
- 重复消息按 `notification_id` 去重，旧 `/api/v1/alerts` 和确认接口保持兼容。

## 8 Python 后端云函数联调配置

后端已提供可替换的微信云函数 HTTP 适配器。默认不开启外部请求，以便离线开发和测试；部署联调环境时设置：

```powershell
$env:WECHAT_FALL_ALARM_PUSH_ENABLED = "1"
$env:WECHAT_FALL_ALARM_PUSH_URL = "https://cloud1-d2gl1av2eb6e440e-1477389215.ap-shanghai.app.tcloudbase.com/fallAlarmPush"
```

每次通知编排触发时，后端向云函数发送：

```json
{"elderId":"E001","riskLevel":"critical","riskScore":86.4}
```

其中 `elderId` 使用后端的 `person_id`，`riskLevel` 使用对外三档值 `low/attention/critical`（内部 `warning` 已映射为 `attention`），`riskScore` 为 0–100 工程风险分。通知详情的 `cloud_push` 字段记录 `sent`、`failed` 或 `not_configured`，以及云函数返回码；不会记录服务器文件路径。

云函数返回 `code=0` 视为成功，其他业务码（如 `-1/-2/-100/-99`）均标记为 `failed` 并保留响应内容。后端请求设置 5 秒超时，不会因云函数异常中断本地告警、WebSocket 或电话兜底状态机。生产环境仍需在网关侧配置 HTTPS、鉴权、限流和供应商密钥管理。
