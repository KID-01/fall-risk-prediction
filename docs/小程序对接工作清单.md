# 微信小程序告警对接工作清单

版本：miniprogram-backend-handoff-v2  
更新时间：2026-08-29

本文档专门列出微信小程序团队需要完成的全部工作。Python 后端现有告警编排、REST、WebSocket、确认接口、30 秒兜底状态机和微信云函数 HTTP 适配器已经完成，后续按本文档联调即可，不需要再重构后端。

## 一、后端当前状态与冻结约束

后端已完成并保持稳定：

- 风险通知等级：`low`、`attention`、`critical`；内部 `warning` 对外映射为 `attention`。
- `attention` 通过 `/ws/alerts` 推送页面提醒。
- `critical` 通过 WebSocket 推送，并记录 APP/SMS 投递状态；30 秒未确认后电话状态变为 `triggered`。
- 调用确认接口后，电话兜底状态由 `scheduled` 变为 `cancelled`。
- 通知列表、详情、策略查询、旧告警查询接口已提供。
- 微信云函数 HTTP 适配器已提供，失败不会阻断本地告警和 WebSocket。
- 通知使用 `notification_id` 去重，不返回服务器绝对路径。

小程序团队不得修改或自行推导以下内容：

- 不要在前端硬编码风险分数阈值或根据分数重新判断等级。
- 不要把 `risk_update` 当作主动告警；主动告警只认 `risk_notification`。
- 不要把工程风险分描述为医学概率或跌倒概率。
- 不要把云函数公网地址写入小程序代码；地址由后端服务端配置。

## 二、云开发团队必须完成的工作

### 1. 部署云函数

- 确认函数名称为 `fallAlarmPush`。
- 使用兼容 HTTP POST 的最新 `index.js`，执行“上传并部署：云端安装依赖”。
- 确认 HTTP 访问已开启，公网路径为 `/fallAlarmPush`。
- 确认函数所在 CloudBase 环境有效，并记录环境 ID、函数版本和部署时间。
- 确认允许函数访问云数据库和微信订阅消息接口。
- 将订阅消息模板 ID 配置到云函数，不要要求 Python 后端直接调用微信 OpenAPI。

### 2. 准备云数据库集合

必须创建并验证以下集合和字段：

- `elder`：`elderId`、`name`；至少准备测试记录 `elderId=E001`。
- `family`：`elderId`、`openid`；为 `E001` 绑定至少一个真机测试家属 OpenID。
- `alert_record`：保存 `elderId`、`elderName`、`riskLevel`、`riskScore`、`alertType`、`alertTime`、`status`。

### 3. 验证云函数返回码

云函数必须保持以下返回约定：

- `code=0`：处理成功。
- `code=-1`：未找到老人。
- `code=-2`：高危但没有绑定家属 OpenID。
- `code=-100`：非法风险等级。
- `code=-99`：内部异常。

`riskLevel` 只接受 `low`、`attention`、`critical`，不得增加橙色或其他对外等级。

## 三、Python 后端联调需要对方提供的信息

请云函数团队向后端提供以下信息：

1. 确认可用的 CloudBase HTTP 公网 URL。
2. 确认 CloudBase 环境 ID 和 `fallAlarmPush` 发布版本。
3. 提供一次低风险 POST 测试结果，响应必须为 `code=0`。
4. 提供 `E001` 测试老人是否存在、是否绑定家属 OpenID 的确认结果。
5. 提供 critical 订阅消息模板 ID 和模板字段映射。

后端只需要在启动服务前设置：

```powershell
$env:WECHAT_FALL_ALARM_PUSH_ENABLED = "1"
$env:WECHAT_FALL_ALARM_PUSH_URL = "<云函数团队确认后的公网 URL>"
```

环境变量变更后重启后端即可，不需要修改风险算法、数据库结构或 REST/WebSocket 代码。

## 四、小程序前端必须完成的工作

### 1. 启动初始化

- 配置后端基础地址，不在代码中写死开发机地址。
- 启动时调用 `GET /api/v1/notifications/policy`。
- 根据返回策略展示三档风险含义和渠道，不自行设置阈值。
- 建立 `/ws/alerts` 连接并显示连接状态。

### 2. WebSocket 长连接

- 本地模拟器可使用 `ws://127.0.0.1:8000/ws/alerts`。
- 真机和生产环境必须使用 `wss://`。
- 每 20–30 秒发送：

```json
{"type":"ping"}
```

- 收到 `{"type":"pong"}` 更新心跳时间。
- 断线后自动重连，使用递增重试间隔，避免高频重试。
- 重连成功后立即调用通知列表接口做断线补偿。

### 3. 主动告警处理

只处理消息：

```json
{"type":"risk_notification","data":{}}
```

必须完成：

- 使用 `data.notification_id` 去重。
- `attention`：普通页面提醒，不显示确认按钮。
- `critical`：强提醒，显示风险等级、分数、原因、截止时间和“我已确认”按钮。
- 同一 `notification_id` 收到 `fallback.state=triggered` 时只更新原记录，不重复弹窗。
- `cloud_push.status=failed` 时显示云端通知失败状态，但不得改变风险等级。
- 兼容接收 `risk_update`，但只用于刷新看板，不触发告警弹窗。

### 4. 高危确认

- 点击确认按钮调用：

```http
POST /api/v1/alerts/{alert_id}/acknowledge
```

- 提交期间禁用按钮，防止重复点击。
- 成功后重新拉取通知详情，确认 `acknowledged=true`。
- 确认后显示 `fallback.state=cancelled`。
- 即使电话兜底已经 `triggered`，仍允许确认并保留“电话兜底已触发”的历史状态。

### 5. 通知历史列表

至少实现以下展示字段：

- 发生时间 `occurred_at`
- 风险等级 `risk_level` 和中文标签 `risk_label`
- 风险分 `risk_score`
- 标题和消息 `title/message`
- 原因码 `reason_codes`
- 是否已确认 `acknowledged`
- 渠道计划 `channels`
- 各渠道投递状态 `deliveries`
- 电话兜底 `fallback.state`
- 云函数状态 `cloud_push.status`

页面进入、下拉刷新和 WebSocket 重连后调用：

```http
GET /api/v1/notifications?acknowledged=0&limit=50
```

支持按 `person_id`、`risk_level`、`acknowledged`、`hours`、`limit`、`offset` 过滤和分页。

## 五、订阅消息与真机工作

- 在微信公众平台申请并配置 critical 使用的订阅消息模板。
- 云函数读取 `family.openid` 并发送订阅消息；小程序前端不直接发送订阅消息。
- 小程序侧完成订阅消息授权引导和拒绝授权后的降级提示。
- 使用真机验证小程序关闭或退后台时，家属仍能收到 critical 订阅消息。
- 模拟器只能验证接口和页面，不能作为订阅消息最终验收依据。

## 六、联调顺序

1. 云函数团队完成部署、数据库集合和 `E001` 测试数据。
2. 云函数团队用低风险示例验证公网 URL 返回 `code=0`。
3. 后端设置环境变量并重启服务。
4. 后端确认通知详情中的 `cloud_push.status=sent`。
5. 小程序读取策略并连接 WebSocket，完成 `ping/pong`。
6. 触发 `attention`，验证只出现普通页面提醒。
7. 触发 `critical`，验证强提醒、订阅消息和确认接口。
8. critical 30 秒不确认，验证原 `notification_id` 的 `fallback.state=triggered` 更新且不重复弹窗。
9. 断开 WebSocket 后重连，验证历史通知补偿和去重。
10. 模拟云函数超时、非 0 返回和 WebSocket 断线，确认小程序展示错误但本地告警链路继续工作。

## 八、后端不会再大改的接口承诺

只要云函数团队保持本文档中的 URL、请求字段和返回码，小程序团队可以按以下稳定契约开发：

- 云函数请求：`elderId`、`riskLevel`、`riskScore`。
- 小程序 REST：策略、通知列表、通知详情、告警确认。
- 小程序 WebSocket：`ping/pong`、`risk_notification`、兼容 `risk_update`。
- `notification_id` 用于去重，`alert_id` 用于确认。
- `fallback.state` 只使用 `null/scheduled/cancelled/triggered`。

后续 APP、短信、电话供应商接入只替换后端适配器，不改变小程序已经对接的通知字段和确认流程。
